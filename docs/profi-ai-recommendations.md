# Интеллектуальный анализ Profi.ru

После построения `profi_current.json` GitHub Actions запускает
`python scripts/profi_analyzer.py`. Используются существующий секрет
`OPENAI_API_KEY` и модель `gpt-5.6-luna`, как в анализе LinkedIn.
Пользователь явно разрешил передачу 12 октября 2026 года:
`enabled: true`, `data_transfer_approved: true`. Оба флага необходимы для запроса.
Профиль охватывает прикладные инженерные задачи вне авиации, включая подтверждённый
стенд Пельтье/STM32, температурное управление, датчики, экспериментальные установки,
Python/PySide6, обработку измерений и автоматизацию. Все заказы рассматриваются;
приоритет определяется содержанием и переносимостью опыта, а не названием отрасли.
Изменять установку на ПК не требуется. GUI, локальный парсер и выключение ПК
работают по прежней цепочке; новый анализ выполняется независимо на GitHub.

Профиль берётся из `profile.json`. Подтверждённая текущая работа над активной
виброизоляцией и 6-DoF стабилизацией добавлена в `profi_analysis_config.json`,
не меняя общий профиль LinkedIn. Числовые характеристики стенда, минимальная
ставка и гарантированная доступность пользователя не заданы.

## Что показывает сайт

Вкладка «Рекомендации» на https://devorvant.ru/profi-monitor.html:

- «Откликнуться», «Уточнить условия», «Пропустить».
- Причина, техническое соответствие, приоритет, уверенность.
- Оценка бюджета и формата, вопросы заказчику, недостающие сведения.
- Основания из карточки и черновик для ручной проверки/копирования.
- Источник: новый ИИ-анализ, сохранённый ИИ-анализ или предварительная оценка по словам.

Баллы не являются вероятностью получения заказа. В отсутствие описания, бюджета,
при предупреждениях парсера или низкой уверенности уверенное «Откликнуться»
понижается до «Уточнить условия». Ставки в час не сравниваются с полной ценой проекта.
Предварительная оценка не получает числовые баллы или ИИ-черновик.
Черновики не отправляются автоматически. Доступность заказа проверяется на Profi.ru.

## Кэш и ошибки

`profi_analysis_cache.json` хранит только успешно проверенные ответы.
Ключ включает ID, содержание/цену/формат заказа, профиль, настройки дополнений,
модель, версию инструкции и схему ответа. Повторное наблюдение того же заказа
не вызывает повторный API-запрос; изменение условий или профиля вызывает.
Ограничение кэша — 3000 записей. Старые рекомендации не показываются для нового
сбора, пока `source_generated_at` и `captured_at` не совпадут с текущими данными.

По умолчанию: до 120 новых заказов за запуск, пачки по 6, таймаут запроса
75 секунд, общий лимит анализа 480 секунд. После двух подряд ошибок API
оставшиеся заказы получают явно обозначенный предварительный отбор.
Отсутствие ключа/ошибка API не препятствуют построению истории и метрик.
Валидируются ID, уникальность и полнота ответов, диапазон баллов, категории
и основания из исходной карточки. Пробелы, регистр и пунктуация могут отличаться,
но цитата на сайте восстанавливается из реального исходного фрагмента: новые слова
не добавляются. Неподтверждённые цитаты отбрасываются; отсутствие хотя бы одной
подтверждённой цитаты отклоняет результат отдельного заказа. Остальные валидные
ответы из той же пачки сохраняются. Ошибочные ответы не кэшируются.

Выход: `profi_recommendations.json` содержит рекомендации последнего сбора,
счётчики источников анализа, предупреждения и использованные токены текущего запуска.
API-ключ берётся только из окружения CI. В модель передаются технические сведения;
имена клиентов, ID клиентов и поля источников профиля не включаются. Контактные
ссылки, email и явно оформленные телефонные номера заменяются маркерами.
Текст заказов трактуется как данные, а не инструкции. Запрос API использует `store: false`.

Проверки:

`python -m unittest discover -s tests -p 'test_profi*.py'`

`node tests/test_profi_ui.cjs`

Тесты используют синтетические заказы и mock API. HTML-фикстура совпадает с
публикуемой страницей; проверяются фильтры, кэш, устаревшие результаты, ошибки,
экранирование, безопасные ссылки и ручное копирование.


## История и актуальность

После каждого анализа `scripts/profi_recommendation_history.py --git-backfill`
строит `profi_recommendation_history.json`: даты, счётчики и ссылки на уже
опубликованные Git-версии существующего `profi_recommendations.json`.
Полные копии названий, условий, объяснений и черновиков в новые файлы истории
не записываются. Сайт читает исходный опубликованный файл по ссылке на его commit.
Последний результат использует ref `main`, который следующий запуск закрепляет
на конкретном commit. Повтор с кэшем не создаёт дубль. Изменение оценки или новый
сбор сохраняются в Git как прежде и становятся доступны в индексе.
Ограничение кэша не затрагивает историю версий Git.

Вкладка «Рекомендации»: источник «Последний сбор» либо «История рекомендаций»,
периоды сегодня/вчера/3 дня/7 дней/месяц/всё или диапазон дат. Архив подгружает
снимки по выбранному периоду. Показывается последняя оценка каждого уникального
заказа за этот период; можно выбрать конкретную сохранённую оценку.

Актуальность определяется временем наблюдения карточки, а не временем повторного
ИИ-анализа или первого обнаружения. Старше 72 часов — требуется проверить заказ.
Архивные оценки помечены как исторические, копирование архивного отклика выключено;
его текст остаётся доступен для ручного просмотра. Даже свежий сбор не гарантирует,
что заказ открыт: перед откликом надо перейти на Profi.ru. Отсутствие в сборе не
трактуется как подтверждённое закрытие.
