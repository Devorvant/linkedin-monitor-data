# LinkedIn → Profi.ru на PC2

Установить `scripts/dispatcher_v4_linkedin_profi.py` в существующую папку
`linkedin_desktop_automation` рядом с `github_token.txt` и `approval_secret.txt`.
В существующем задании Планировщика Windows заменить путь старого диспетчера
на этот файл (либо сохранить новый файл под прежним именем диспетчера).
Не создавать второе параллельное задание. Python и аргументы запуска оставить прежними.
GUI требует того же активного пользовательского сеанса, что и прежняя автоматизация.

Диспетчер скачивает актуальный `linkedin_worker_entry.py` из `control.json`.
Цепочка PC2: LinkedIn → прежние одобренные действия → пауза 60 секунд →
актуальный Profi.ru collector/parser. При штатной работе окна закрывают прежние
GUI-функции worker. Парсинг остаётся на ПК; Profi.ru передаёт прежний JSON в GitHub.

## Время и защита

Расписание сохранено: START 08:10, FINISH 08:20 по локальным часам Windows.
FINISH вычисляется один раз и не переносится на завтра после ошибки.
До ожидания START и запуска worker диспетчер ставит независимый таймер Windows
`shutdown /s /f /t …`. Он действует и после аварийного выхода Python.
Если Windows отклонит команду, это записывается в лог; собственный контроль FINISH
остаётся и повторяет команду в конце. Успех зависит от Windows и прав пользователя.

Этапы запускаются последовательно в отдельных процессах. Windows Job Object
ограничивает дочерние процессы; таймаут останавливает Job и использует
`taskkill /PID … /T /F`. Если процесс не остановился, Profi.ru блокируется.
Ожидание worker без таймаута устранено. Отправка диагностики также ограничена FINISH.

Если после LinkedIn осталось менее 180 секунд (пауза 60 + минимум 120 для Profi.ru),
Profi.ru пропускается с причиной `skipped_finish`. Даже начавшийся Profi.ru
ограничен FINISH. Расписание должно вместить реальную длительность двух сборов;
этот пакет не меняет время выключения.

Настройки `control.json`:

- `linkedin_enabled`: временное включение сбора LinkedIn и связанных одобренных действий.
  При `false` оба этапа пропускаются, а Profi.ru на PC2 запускается без паузы после LinkedIn.
  Время START/FINISH и независимый таймер выключения сохраняются.
  Текущий режим — `false` (только Profi.ru); для возврата полной цепочки установить `true`.
  Если параметр отсутствует, для совместимости действует прежняя полная цепочка.
- `profi_after_linkedin.enabled`: включение Profi.ru.
- `profi_after_linkedin.delay_seconds`: пауза 60.
- `profi_after_linkedin.timeout_seconds`: максимум Profi.ru 300.
- `profi_after_linkedin.min_remaining_seconds`: минимум после паузы 120.
- `linkedin_timeout_seconds`: 900; `actions_timeout_seconds`: 180.
- `worker_timeout_seconds`: максимум всей цепочки 1200.
- FINISH имеет приоритет над всеми максимальными длительностями.

Ручной запуск на ноутбуке не добавляет Profi.ru или автоматическое выключение.
Старый диспетчер получает новый entry, который может определить FINISH на PC2
внутри рабочего окна. Полный контроль внешнего процесса и ожидания START
требует нового локального диспетчера.

## Диагностика

Ошибка LinkedIn пропускает одобренные действия; после безопасного завершения
Profi.ru может выполниться, если остаётся время. Ошибка Profi.ru возвращает ненулевой
код, но не отменяет выключение. При отсутствии сети диагностика остаётся локально.
При недоступном `control.json` используется последний валидный локальный файл.
Если нет обеих конфигураций, диспетчер выполняет аварийное выключение.
Ctrl+C отменяет только таймер, установленный этим запуском.

В `logs`: `dispatcher_current.log`, `worker_latest.log`, `linkedin_latest.log`,
`actions_latest.log`, `profi_latest.log`, `chain_status.json`, `*_status.json`.
Локальный `dispatcher_status.json` содержит результат цикла. При доступной сети
и запасе времени прежние `logs/dispatcher_latest.log` и `dispatcher_status.json`
в GitHub получают объединённую диагностику с `chain`. При достижении FINISH
последние записи могут остаться только локально. Очистка LinkedIn защищает файлы Profi.ru.

## Проверка

`python -m unittest discover -s tests -p 'test_automation*.py' -v`

Синтетические процессы и имитация ошибок/часов; команды выключения заменены mock.
Реальный браузер и данные не используются. Первый запуск на ПК проверяет координаты
монитора, закрытие окон и фактическое выключение. GUI-функции и парсер Profi.ru не изменены.
